# Authored threat notes

Select a node or flow and choose **Add threat note** in its Issues section,
or open **Review > Issues** with that node/flow selected. Enter an optional
title and free-form multiline **Threat / mitigation notes**. **Justification**
is optional; title, body and justification may all be blank. There is no required
template, prose parser, mitigation catalog, risk acceptance state or completion
gate. Severity is unspecified; no CVSS score or band is inferred.

The note applies to the active scenario. In Show all, it applies to every
scenario containing that target. The editor labels its captured target and
applicability; changing selection while editing does not retarget that draft.
Use the existing issue Details/Edit, Resolve/Reopen, replies and Delete
controls. Active/Resolved is a human review decision, not proof that a proposed
mitigation is implemented or effective. Analyze preserves these notes.

Only explicit authoring sets `PsIssue.origin: "authored-threat"`. An ordinary
comment, old untyped issue, accepted AI finding or analyzer issue does not gain
this identity. There is no bulk conversion. Notes reuse the existing issue
collection, stable IDs and compatible-peer Yjs maps.

## Native durability and lifecycle

`.tma`, autosave (including undo/redo history) and portable application HTML
preserve authored content, identity and human status. Review reports display
the applicable notes and supplied justification; Compare to previous identifies
changes to authored notes. Neither replaces the native model as a backup.
Justification remains separate exact text in the native model. Invalid authored
fields or missing targets/scenarios block import/recovery rather than silently
discarding text or widening applicability. Recovery leaves the original saved
data untouched. Use compatible application versions for shared editing;
older readers may not preserve additive fields.

Deleting a target removes its notes through existing undoable deletion.
Removing a selected scenario from a scoped note removes that scope. If it was
the last selected scenario, the note is removed, not made global; the relevant
removal confirmation describes that impact and Undo restores it. Global notes
remain attached to surviving targets. Scenario duplication copies graph
membership, not selected-scenario note applicability.

## TM7 projection: native records, not annotations

The writer uses only the existing exported occurrence index and minimal SDS
KnowledgeBase. It emits native User-defined threat records with an **empty
string TypeId**, not nil or a custom threat type/stencil.

| Authored content | Native representation |
|---|---|
| Title | `Properties.Title` |
| Multiline threat/mitigation prose | `Properties.UserThreatDescription`, in a labeled block per note |
| Optional justification | `Properties.StateInformation`, labeled per note; blank stays blank |
| Identity, applicability, human state | Explicit note ID, scenario name/ID and SDS Active/Resolved text inside each block |
| Node target | Actual node `SourceGuid`; `FlowGuid` and `TargetGuid` are Guid.Empty; actual tab GUID |
| Flow target | Actual source/flow/target GUIDs and actual tab GUID |

No text is parsed into separate mitigation claims. `PossibleMitigations` is
blank; authors' mitigation prose remains in the description. Ordinary
discussion/replies and non-authored findings are not exported.

**Multiplicity limitation:** the tested native dashboard rejects independent
empty-TypeId records sharing an interaction even when their dictionary keys
and numeric IDs differ. The writer therefore aggregates all notes for that
interaction into one native record, retaining separately labeled exact
titles, bodies, supplied justifications, IDs, statuses and applicability.
This is an external-format projection, not a limit on authoring notes.

**Repeated-tab limitation:** native interaction identity omits the tab.
An interaction spanning applicable tabs is projected onto its first
represented applicable tab in export order, never duplicated or redirected to
a made-up flow. Each note's original applicability remains explicit text.
Aggregation and tab projection are disclosed before download; cancel to keep
only `.tma`. Missing/ambiguous invalid target references block export.

**Workflow and priority:** every native record uses the observed native
`AutoGenerated` / **Not Started** workflow default. It is not a translation of
SDS Active/Resolved, not "Mitigated", and not a risk decision. Each note's human
status is preserved in its own text block, including mixed-status aggregates.
`Properties.Priority` is exported empty (unspecified). In actual exporter
acceptance, TMT assigned **High to both current and legacy Priority and
displayed High**, and assigned SDL phase Design. These are native format
defaults, not authored severity, CVSS or lifecycle decisions. Every note's
labeled text explicitly retains **SDS severity: Unspecified**. The writer does
not claim blank native severity survives saving. A separate earlier control
preserved the current blank value but is not evidence for this exporter; no
importer should override an explicit blank current property using legacy High.

The pre-export confirmation discloses these limitations even for a blank
note. **Keep `.tma` as the full-detail original.** TM7 re-import deliberately
does not reconstruct threat notes, status or justification; its loss preview
appears before replacement. It does not import legacy Priority as severity.

## Evidence boundaries

Synthetic pure tests cover provenance, exact text, native serialization,
aggregation, projection, invalid references, report/diff, recovery and
compatible-peer propagation. Native node GUID persistence plus the correct
visible row/tab/text is the bounded node association contract; automatic
canvas highlighting/navigation is not claimed. XML tests and compilation are
not native open/save/reopen evidence. Exact candidate native acceptance,
browser interaction and human usability results must be recorded separately.
